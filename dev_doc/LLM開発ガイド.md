# Godot Recipes 開発ガイド（LLM向け）

このファイルは、`godot_recipes` リポジトリで作業するLLMや開発者が、作業前に読むべきプロジェクト仕様・運用ルール・検証手順をまとめたものです。

## 1. プロジェクト概要

- プロジェクト名: Godot Recipes（Godotレシピ）
- 目的: KidsCanCodeの「Godot Recipes」を基にした、Godotゲーム開発チュートリアル・実装例の非公式日本語翻訳サイト
- サイト生成: Hugoによる静的サイト生成
- 主な対象バージョン: Godot 4.x
- 公開先: GitHub Pages
  - 日本語版: `https://kamera25.github.io/godot_recipes/4.x/ja/`
  - 原文サイト: `https://godotrecipes.com/`
- ライセンス:
  - テキストコンテンツ: CC BY 4.0
  - コードサンプル: MIT License
  - 日本語訳にはPLaMoコミュニティライセンスの対象となる翻訳が含まれる

このリポジトリは単独のGodotゲームプロジェクトではなく、Godotの技術記事を公開するドキュメントサイトである。記事内にはGDScriptのコード例が含まれる。

## 2. ディレクトリ構成

| パス | 役割 |
| --- | --- |
| `src-4/` | Godot 4.x向けHugoサイトのソース。通常の編集対象 |
| `src-4/content/` | 記事・カテゴリのMarkdown |
| `src-4/layouts/` | Hugoテンプレートの上書き |
| `src-4/config.toml` | Hugo設定、言語設定、公開先、サイトメタデータ |
| `src-4/static/` | Godot 4.xサイト固有の静的ファイル |
| `src-3/` | Godot 3.x系の旧ソース。Godot 4.xの通常作業では変更しない |
| `themes_shared/` | 共有Hugoテーマ |
| `static_shared/` | 3.x/4.xで共有する静的ファイル |
| `docs/` | Hugoのビルド出力。原則として直接編集しない |
| `scripts/` | 補助スクリプト置き場 |
| ルート直下の`*.py` | 翻訳、リンク、Markdown、GDScript断片などの保守用スクリプト |
| `dev_doc/` | 開発者・LLM向けの内部ドキュメント |

### コンテンツの分類

`src-4/content/` には、主に次のカテゴリがある。

- `g101/`: Godot入門
- `basics/`: 基礎
- `2D/`: 2Dゲーム開発
- `3D/`: 3Dゲーム開発
- `ai/`: AI・経路探索など
- `animation/`: アニメーション
- `input/`: 入力
- `physics/`: 物理
- `shaders/`: シェーダー
- `ui/`: UI
- `games/`: ゲーム制作チュートリアル
- `kyn/`: 追加・派生コンテンツ

カテゴリ名は既存の大文字・小文字を維持する。新しい記事を置く前に、近い内容の既存記事とカテゴリの`_index.md` / `_index.ja.md`を確認する。

## 3. 翻訳・記事ファイルの仕様

### 原文と日本語訳の対応

- 原文記事: `article.md`
- 日本語訳: `article.ja.md`
- カテゴリトップも同様に、`_index.md` と `_index.ja.md` を対応させる
- 原文と日本語訳は同じディレクトリ・同じベース名で管理する
- 原文に対応する日本語訳がない場合、勝手に別名を作らず、既存の命名規則に合わせる

翻訳ファイルを編集する際は、文章だけでなく次の構造を保持する。

- Front matterのキー、型、値の意味
- Hugoの見出し階層
- コードフェンスとコード本体
- Hugo shortcode（`{{% ... %}}` / `{{< ... >}}`）
- 画像、リンク、アンカー、HTMLタグ
- `gd-icon`などのアイコンshortcodeの数と位置

コードブロックは翻訳しない。コード内の識別子、ノードパス、入力アクション名、ファイル名、API名も原則変更しない。説明文中のAPI名・クラス名・メソッド名はバッククォートで囲み、実際のGodot 4.x APIと一致させる。

### Front matter

既存ファイルの形式に合わせる。カテゴリページなどではTOML形式（`+++`）、記事ではYAML形式（`---`）が使われているため、形式を混在させたり、不要なキーを追加したりしない。

最低限、既存ページにある次の情報を壊さない。

- `title`
- `description`
- `date`
- `draft`
- `weight`
- `chapter`
- `pre`

日本語ページでは、日本語の`title`と`description`を設定する。URLに影響するファイル名は、既存の英語ファイル名を原則維持する。

## 4. Hugo設定とビルド

主要設定は `src-4/config.toml` にある。

- `defaultContentLanguage = "en"`
- 英語・日本語の2言語を設定
- 英語と日本語は同じ `contentDir = "content"` を共有
- 出力先は `../docs/4.x`
- テーマは `hugo-theme-relearn-main`
- `themesDir = "../themes_shared"`
- `staticDir` は `static` と `../static_shared`
- 本番ビルドではminifyが有効

ローカルで確認する場合は、リポジトリルートではなく `src-4/` をHugoの作業ディレクトリにする。生成物は `docs/4.x/` に作られるため、生成後に差分を確認し、生成物を手編集しない。

GitHub Actionsでは、`main`または`master`へのpushと手動実行を契機に、Hugo `0.164.0`（extended）で `src-4` をビルドし、`docs`をGitHub Pagesへデプロイする。

## 5. 変更作業の基本手順

1. 変更対象と既存の対応記事を特定する。
2. 変更前に `git status --short` で、他の作業者の変更を確認する。
3. 原文・日本語訳・カテゴリインデックスの関係を確認する。
4. 必要最小限のファイルだけを編集する。
5. Markdownの構造、shortcode、リンク、コードブロックを確認する。
6. 翻訳や記事を変更した場合は、可能な範囲でHugoビルドを実行する。
7. GDScriptコードを変更した場合は、構文検査を実行する。
8. 変更後に `git diff --check` と `git status --short` を確認する。
9. 生成物を変更した場合は、その変更が意図したビルド結果か確認する。

既存の未コミット変更はユーザーの作業である可能性がある。依頼された範囲と関係のない変更を整形・削除・巻き戻ししない。

## 6. 既存の検査・保守スクリプト

ルート直下のスクリプトは、実行前に対象パスとスクリプトの設定値を確認する。古い絶対パスを前提にしているものがあるため、実行すれば必ず現在のリポジトリを検査できるとは限らない。

| スクリプト | 用途 |
| --- | --- |
| `scripts/checks.sh` | PO、Python、GDScript、生成HTMLの検査をまとめて実行 |
| `scripts/checks/` | GDScript、リンク、POの個別検査スクリプト |
| `scripts/i18n.sh` | Markdown/HTMLとPOの抽出・更新・適用をまとめて実行 |
| `scripts/i18n/` | 翻訳対象の抽出・PO更新・日本語適用スクリプト |
| `scripts/maintenance/` | POリンク補正や手順文分割などの保守用スクリプト |

POファイル（`output.po`、`docs_extracted.po`、`messages.mo`など）を変更する場合は、翻訳処理の中間生成物か、正式な管理対象かを確認してから扱う。単発の翻訳修正で、機械的に全POを再生成しない。

## 7. Godot 4.x記事の記述ルール

- Godot 4.xのAPIを優先する。Godot 3.xのクラス名・プロパティ名を新規記事へ持ち込まない。
- `KinematicBody2D`などGodot 3.x由来の名称が既存記事に残っている場合、対象記事の意図と互換性を確認してから修正する。
- GDScriptのインデントは既存コードに合わせる。一般にスペース4個を使用する。
- `@export`、`@onready`、`CharacterBody2D`、`move_and_slide()`など、バージョン差のある構文は実際のコード例と説明文で一致させる。
- コードサンプルは記事の説明だけでなく、ノード構成、入力アクション、Collision Layer/Mask、必要なリソースも確認できるようにする。
- サンプルコードを変更した場合、説明中のノード名・変数名・スクリーンショットとの不一致がないか確認する。

## 8. 文章・翻訳の品質基準

- 日本語として自然で、初心者にも手順が追える文体にする。
- 原文の技術的な意味、条件、注意事項、前提を省略しない。
- UI名・メニュー名は、Godot日本語UIの正式表記が確認できない場合、英語表記を併記する。
- 固有名詞、API、ファイル名、パス、コード要素は原文のまま保持する。
- 直訳で意味が不自然になる場合は、実装意図を優先して意訳する。ただし、処理内容を追加・変更しない。
- リンク先を日本語版へ置き換える場合は、実際に存在するパスだけを使用する。存在しない日本語記事へのリンクを推測で追加しない。
- 非公式翻訳であることやライセンス表記を損なわない。

## 9. 変更してはいけない・慎重に扱うもの

- `docs/`のHTMLやRSSなどの生成物を、ソースを直さず手動で編集しない。
- `themes_shared/`や`static_shared/`の変更は、3.xと4.xの両方へ影響する可能性があるため、依頼の範囲を確認する。
- `src-3/`は旧バージョン用であり、4.x記事の修正のつもりで触らない。
- `.github/workflows/deploy.yml`のHugoバージョン、公開ブランチ、出力先を理由なく変更しない。
- `.gitignore`で除外されているキャッシュやビルドロックを、成果物として追加しない。
- 既存のリンクURL、canonical、言語切り替え設定、ライセンス表記を一括置換しない。

## 10. 完了条件

作業は次を満たした時点で完了とする。

- 依頼内容が対象ソースに反映されている。
- 原文・日本語訳・カテゴリインデックスの構造が破綻していない。
- コードブロック、shortcode、リンク、Front matterが保持されている。
- 可能な範囲でHugoビルドまたは対象の検査を実行し、結果を確認している。
- `git diff --check`で空白エラーがない。
- 依頼と無関係なファイルを変更していない。
- 最終報告では、変更したファイル、検査内容、未検証の点があれば簡潔に記載する。

## 11. LLM向け判断優先順位

判断に迷った場合は、次の順で優先する。

1. ユーザーの明示的な依頼
2. この記事・カテゴリに既にある記述と命名規則
3. `src-4/config.toml`とCIの実際の設定
4. Godot 4.xの公式仕様との整合性
5. このドキュメントの一般ルール

このガイド自体と実際のリポジトリの状態が異なる場合、リポジトリの実態を優先し、必要ならこのガイドも更新する。
