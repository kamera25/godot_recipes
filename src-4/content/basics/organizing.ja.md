## Problem

新しいプロジェクトを開始しましたね。間もなく、プロジェクトフォルダにはシーン、アセット、スクリプトなどが膨大に増えていきます。これらをどう整理していけばよいでしょうか？

## Solution

このゲーム開発の問題には、ゲームプロジェクトの数だけ解決策が存在します。適切なアプローチは、制作するゲームの性質や必要なリソースによって大きく異なります。ただし、以下に挙げる基本的なガイドラインのいくつかは普遍的に適用できます。

### 種類別に整理する

初心者の方がよくこのような形でプロジェクトを整理します。

![alt](/godot_recipes/3.x/img/organize_01.png)
<!-- ```markdown
- res://
    - scenes
    - scripts
    - images
    - ...
``` -->

**これは絶対にやめてください！** すべての `.gd`ファイルを同じフォルダにまとめておくことは一見整理されているように見えますが、プロジェクトが成長するにつれて、スクリプトでいっぱいになったフォルダの中から必要なものを探すのが困難になります。

### カテゴリ別に整理する

一般的な解決策として、プロジェクトファイルをゲーム機能ごとに階層化したフォルダ構造に分割する方法があります。例えば、以下のような構成が考えられます。

![alt](/godot_recipes/3.x/img/organize_02.png)

<!--
```markdown
- res://
    - assets
        - textures
        - sounds
        - models
    - objects
        - entities
            - player
            - enemy
        - maps
    - UI
    - ...
``` -->

このシステムでは、シーンやスクリプトなど共通の目的を持つファイルをすべて同じディレクトリに配置します。大規模プロジェクトでは、この手法が非常に重要になります。ファイル数が増えすぎると管理が困難になるため、このような整理方法が効果的だからです。

### 再利用性を考慮した設計

上記の方法の欠点は移植性に乏しい点です。別プロジェクトで同じ「Player」オブジェクトを使用しようとする場合、複数フォルダから個別ファイルをコピーする必要があります。一方、プレイヤー関連のすべての要素（シーン、スクリプト、アセット）が同じフォルダ内にまとまっていれば、プロジェクト間で簡単に移動でき、全体をそのまま維持できます。
